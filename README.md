# Exlink3.1 — 一机多用的掌上多功能仪器（MP28167 数控电源版）

> **本目录 = Exlink3.0 + Exlink1.1 的 MP28167 驱动**：调压芯片从原版 Exlink 的 MCP4017 数字电位器
> 换成 **ExlinkPro 板上的 MP28167**（MPS 四开关 buck-boost，I2C 写参考电压，0–20 V 线性可调）。
> DC POWER 页新增 **SET xx.x V 输入框**（点开数字键盘输入；`+/-` 微调 0.1 V；11V/5V/3V 预设）。
> 驱动在 `src/app/mp28167.cpp`（I2C 地址 0x60、寄存器 0x00/0x01/0x02、换算公式沿用 Exlink1.1 实测值），
> 总线锁与“写失败 100 ms 重试”沿用 3.0 的 power 任务；其余架构与 UI 模型同 3.0。

## Exlink3.0 — 一机多用的掌上多功能仪器（第一版）

**一台设备 = 一个工作台。** 把调试台上分散的多台仪器/工具集成到一台 320×240 触摸手持设备，
功能可同时在线，让工作台更简洁、使用更方便。

- 平台：ESP32-S3（Xtensa 双核 240 MHz）+ FreeRTOS + LVGL 8 + PlatformIO
- 界面：**主菜单按键就地变成功能页面**（EXlink2.1 模型），多个功能页可同屏，页面右下角 × 关闭
- 规模：10 个功能界面，覆盖 **8 类常用仪器/工具**，最多 **6 个功能同时在线**
- 资源：固件 1.52 MB（Flash 占用 **10.1%**）、静态 RAM 123 KB（**38.5%**）
- 自检：串口会打印 `[ui] page open/closed (n, free heap …)`，可在板子上核对同屏页面数与剩余堆

## 设计目标

| 传统工作台的问题 | Exlink3.0 的设计 | 用户收益 |
| ---------------- | ---------------- | -------- |
| 多台台式仪器堆叠、接线杂乱 | 一台手持设备集成 8 类功能 | **工作台更简洁**，随取随用 |
| 一台仪器一次只干一件事，边供电边测频要来回插拔 | 多任务并行 + 后台常驻 | **使用流程不被打断** |
| 各仪器界面/旋钮/菜单各不相同 | 统一 UI 与统一双输入（触摸 + 旋钮） | 学习成本低，上手即用 |
| 不清楚还有哪些功能开着 | 主菜单 RUN 状态 + 按钮高亮 | 设备状态一眼看清，避免漏关输出 |
| 临时接线要查引脚定义 | 内置 Pin Map 彩色接线图 | 现场不用翻资料 |

## 界面模型：菜单按键 <-> 功能页面（EXlink2.1 模型）

原来的界面是"点一个功能就整屏切换"：一屏只有一个功能，返回主菜单才能开下一个。
现在改成 EXlink2.1 的模型——**菜单按键就地变成该功能的功能页面**：

\`\`\`
+--------------------------+  点击  +--------------------------+
| [ Pin Map         icon ] |  --->  | [ Pin Map 页面      x ]  |
| [ DC POWER        icon ] |        | [ DC POWER        icon ] |
| [ PWM OUT         icon ] |        | [ PWM OUT 页面      x ]  |
+--------------------------+        +--------------------------+
\`\`\`

- **就地替换**：每个菜单项由「按键 + 功能页」两个对象组成，二者在菜单列的同一个 flex 流里；
  打开页面 = 按键隐藏、页面显示，页面就出现在原来按键的位置；× 关闭则反过来。
- **大小自适应**：页面宽度 = 菜单列宽（\`LV_PCT(100)\`），高度 = \`LV_SIZE_CONTENT\`（随内容），
  页内用 flex + 百分比排布。
- **多页同屏**：可以同时开好几个功能页，后台任务照跑（开关与界面本来就解耦）。
- **焦点单位是"整个页面"**：旋钮/方向键/右侧滑条的单位是"一个菜单项"——功能没开时是菜单按键，
  开了以后是**整页**（金色边框），不会选中页面内部的控件（内部控件用触摸点击）；
  焦点一变就把该页完整滚进屏幕（\`keep_focus_visible()\`）。
- **返回键**：右滑 / 长按 / 旋钮长按 = 关掉"当前焦点所在的功能页"，不再重建整个主菜单。

### 后端适配检查（任务层需要改的地方）

任务层（\`src/app/task_*.cpp\`）本来就不碰任何控件——它们只写 Stream Buffer / 环形缓冲 /
互斥共享结构，控件刷新由界面侧的搬运定时器完成。所以"多页常驻"对任务层**基本无影响**，
审计后只有三处需要动：

| 位置 | 原实现 | 问题 | 改法 |
| ---- | ------ | ---- | ---- |
| \`app_ui_page_set()\`（单值页面） | 一个 \`app_page_t\` 变量 | 多页同屏时"当前是哪一页"没有意义，\`app_ina_demand()\` 会判断错采样档位 | 新增 \`app_ui_page_open/close/is_open\`（位图，多值），\`app_ui_page_set\` 保留兼容语义 |
| \`app_ina_demand()\` | 只在"当前页 == DC POWER/Voltmeter"时 100 ms 全量采样 | 两个页面同开、页面与主菜单同屏时判错 | 改成"**任一** 页面开着就 100 ms 全量采样"；主菜单始终可见（电池图标），所以其余情况为 1 s 采电池 |
| 界面侧搬运定时器 | \`updatelabel_timer1..3\`/\`adddata_timer*\` 等**全局**变量，且 POWER 与 Voltmeter 共用 | 两个页面同时打开时全局变量互相覆盖（一个页面的定时器会被另一个删掉/覆盖） | 定时器改为**每个菜单项一份**（\`exlink_entry_t.timers[]\`），随页面开关创建/删除；图表喂数据改为 \`chart_feed_t\`（chart + series） |

不需要改动的地方（已逐一确认）：

- **功能开关与任务**：\`app_*_set()\` / \`app_set_output()\` / \`app_i2c_scan_request()\` 原样可用，
  页面上的按钮回调只是把同样的调用接过去；关页面**不关功能**（DC 输出、PWM、BLE、串口、
  频率计、DSO 采样都继续在后台跑），与原固件"返回主菜单不关功能"的语义一致。
- **数据通道**：Stream Buffer / 环形缓冲 / 互斥共享结构不变；界面定时器仍随页面删除，
  后台任务依旧不会持有已销毁的控件指针（页面这里是**隐藏**而不是销毁，更安全）。
- **DEMO 页专用开关**：DSO / 频率计的 RUN/STOP 保留在页面里；与原固件一样，打开页面即
  \`app_dso_set(true)\` / \`app_freq_set(true)\`（可再按 STOP 停）。
- **触摸 / 旋钮 / 蜂鸣器**：\`main.cpp\` 的输入设备、长按发 \`LV_EVENT_LONG_PRESSED\`、
  蜂鸣器与看门狗逻辑不动。

> 资源影响：旧界面是 SquareLine 生成的 10 个整屏（每个整屏都带完整的绝对坐标布局），
> 新界面是紧凑的页面 + 复用样式，**Flash 从 12.3% 降到 10.1%**（省 349 KB）；
> 静态 RAM 基本不变（125,384 → 126,056 B）。10 个页面在开机时一次性建好并常驻，
> 走的是 \`LV_MEM_CUSTOM=1\` 的 malloc（内部 RAM），因此文本框上限从 4000 字符收到 1200 字符
> （页面本身也只有几行高），避免长时间运行堆内存增长。

## 架构：9 个 FreeRTOS 任务 + 双核绑定

UI 固定 core 1（避开 core 0 上无线协议栈抖动），外设任务集中 core 0，按实时性分级设优先级与栈深。
**任务的"周期"只在有需求时成立**：前端没调用时任务阻塞，不空转轮询（见下一节）。

| 任务 | 核心 | 优先级 | 栈 | 有需求时 | 没需求时 | 职责 |
| ---- | ---- | ------ | -- | -------- | -------- | ---- |
| `lvgl` | 1 | 3 | 8 KB | 5 ms | 5 ms（屏幕一直在显示） | 唯一的 LVGL 访问者：界面刷新、事件回调、图表搬运 |
| `ina226` | 0 | 2 | 4 KB | 100 ms（功率/电压表界面或输出打开）<br>1 s（只为主菜单电池图标） | **阻塞** | 电压/电流/功率/mAh + 电池电量 |
| `power` | 0 | 2 | 3 KB | 事件触发（设定值变化） | **阻塞** | 输出开关 + MP28167 调压 |
| `uart` | 0 | 2 | 4 KB | 20 ms（串口助手或 BLE 打开） | **阻塞** | 串口收发，BLE 连接时同步转发 |
| `ble` | 0 | 2 | 10 KB | 200 ms（蓝牙打开） | **阻塞**（且不初始化协议栈） | BLE 广播/连接/收发 |
| `dso` | 0 | 2 | 3 KB | 1 ms（RUN） | **阻塞**（不采样） | ADC 1 kHz 采样 → 256 点环形缓冲 |
| `freq` | 0 | 2 | 3 KB | 125 ms（RUN） | **阻塞**（并暂停 PCNT 计数） | PCNT 频率计数 |
| `pwm` | 0 | 1 | 3 KB | 事件触发（设定值变化） | **阻塞**（LEDC 硬件持续输出） | LEDC PWM 输出 |
| `i2cscan` | 0 | 1 | 4 KB | 事件触发（点 SCAN） | **阻塞**（首次扫描才占用引脚） | I2C 总线扫描 |

中断只保留 1 ms 硬件定时器做图形库心跳（`lv_tick_inc(1)`），中断服务保持极短。

## 任务按需唤醒：前端不用就不占 CPU

第一版的任务循环是"周期 `continue` 轮询"：即使串口、BLE、扫描、示波器全关着，
每个任务也每隔 20–200 ms 醒一次去看一眼开关，白白占用 CPU。现在改成**事件驱动 + 空闲阻塞**：

- 每个任务循环末尾统一调用 `app_task_wait(任务, 周期, 有没有需求)`：
  - **有需求** → `ulTaskNotifyTake(pdTRUE, 周期)`：按周期睡，但状态一变就被打断，响应不受周期限制；
  - **没需求** → `ulTaskNotifyTake(pdTRUE, portMAX_DELAY)`：真正阻塞，CPU 占用为 0；
- 唤醒源有两类：**功能开关**（`app_*_set` / `app_set_output` / `app_i2c_scan_request`）与
  **界面开关**（打开/关闭功能页时登记 `app_ui_page_open()` / `app_ui_page_close()`）；
- 通知用任务通知（`xTaskNotifyGive`）而不是标志位：通知会被计数保存，任务正忙时也不会丢事件，
  所以"按下开关 → 任务动作"没有轮询延迟（例如 DC 输出开关从"最坏 50 ms"变成"立即"）；
- 需求由**界面 + 开关共同决定**：`ina226` 在 DC POWER / Voltmeter 页面开着、或输出打开时全速采样，
  否则降到 1 s 采一次电池（新界面里主菜单始终可见，电池图标要显示）；`pwm` 配好 LEDC 后
  由硬件输出波形，任务本身不再需要周期唤醒；`freq` STOP 时连 PCNT 硬件计数一起暂停；
  `ble` 没打开时连 `BLEDevice::init()` 都不做；`i2cscan` 第一次点 SCAN 才 `Wire1.begin()` 占用引脚。
- 副作用是精度反而更好：`mAh` 改成按两次采样的**真实时间间隔**积分，不再假设"循环正好 100 ms"；
- 建任务与登记句柄统一走 `app_task_start()`（建失败会打印一行而不是静默不工作），
  登记之前到达的唤醒会按位记账、在任务首次等待时补发，不会出现"任务睡死、功能不响应"。

## 数据通道设计

```
硬件任务 ──写──> Stream Buffer(4KB) / 环形缓冲 / 互斥共享结构 ──界面定时器搬运──> LVGL 控件
   ▲                                                                             │
   └──────────────── 界面按钮回调写功能开关（app_*_set）─────────────────────────┘
```

- 图形库**单访问者模型**：LVGL 只在 `lvgl` 任务（含其内部定时器与事件回调）里访问，其它任务不碰控件；
- 文本类（串口 / BLE / 扫描结果）：FreeRTOS **Stream Buffer**（3 × 4 KB）；
- 测量值（V/A/W/mAh/电池）：互斥锁保护的共享结构 + 字符串快照，杜绝数据撕裂；
- 波形：256 点环形缓冲 + 递增序号，界面只取新增点，不丢不重；
- 界面侧搬运定时器在**关闭功能页**时删除（`exlink_close_function()`）→ 后台任务既不会持有
  已销毁的控件指针，也不会往没人在看的页面里搬数据；这是功能可以后台常驻的前提。

## 使用说明

1. 点主菜单的功能键 → 该按键**就地变成功能页面**（可以同时开好几个）；
2. 页面里点 **OPEN**（电源是电源图标按钮；示波器、频率计是 **RUN/STOP**）打开功能；
3. 关页面有三种方式：点页面右下角的 **×**、**右滑**、**长按旋钮**——关的只是界面，
   **功能不会停**，继续在后台运行；
4. 主菜单右侧显示 `RUN n` 与运行中的功能名（PWR / PWM / UART / SCAN / DSO / BLE / FRE），
   对应的菜单按键/页面同步变绿；重新打开页面即可看到后台已攒好的数据；
5. 旋钮（或方向键）用来在菜单项之间移动焦点：没打开的项是按键、打开的项是**整页**（金色边框）；
6. 因此可以 **PWM 持续输出 + BLE 无线收包 + 频率计计数 + 电流实时监测** 同时进行；
7. 波特率下拉框改变后立即对任务生效。

## 硬件限制（务必了解）

- **PWM OUT 与 FRE Count 共用 GPIO5**：同时打开时频率计测到的是自己的 PWM 波形，测外部信号时请关闭 PWM 输出；
- **USB 串口被串口助手与 BLE 转发共用**：BLE 打开并连接后，串口收到的数据会同时转发到 BLE；
- **电流监测模块未接入**时：界面正常运行（显示 0）；只在 DC POWER / Voltmeter 界面打开或输出打开时
  才会去探测，未找到则每 5 秒重试一次（没需求时不扫描总线，串口也就不再刷重试提示）；
- **BLE 首次打开**内存占用较大（工程已开启 `-DBOARD_HAS_PSRAM`，建议使用带 PSRAM 的 S3 模组）；
- 触摸、电流监测、MP28167 共用 `Wire`：已加总线互斥锁，触摸取不到锁时跳过本帧，不会卡界面。
