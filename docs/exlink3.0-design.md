# Exlink3.0 设计精简文档

> 一台 ESP32-S3（320×240 触摸）掌上设备，覆盖 8 类调试仪器，最多 6 个功能**同时在线**。
> 本文只讲"为什么这么设计"和"关键实现"，数据均取自本仓库代码。

---

## 1. 一句话

传统仪器**一台一次只干一件事**：边供电边测频、边看串口边扫 I2C，就得来回插拔换设备，工作台线越接越多、工具反而打断工作流。
Exlink3.0 用一台手持设备替代它们，并把"并行"做成默认能力——**返回主菜单不关功能，仪器在后台继续跑**。

| 项目 | 内容 |
| ---- | ---- |
| 定位 | 掌上多功能仪器（可调电源 / 电压表 / PWM 源 / 简易示波器 / 频率计 / 串口助手 / BLE 无线串口 / I2C 扫描 + 引脚图） |
| 硬件 | ESP32-S3 双核 240 MHz，SPI TFT 320×240 + CST816T 触摸 + 旋转编码器 + 蜂鸣器；INA226 / MP28167（3.1；3.0 为 MCP4017）；12 位 ADC、LEDC、PCNT |
| 软件 | Arduino-ESP32 2.0.14（ESP-IDF）+ FreeRTOS(SMP) + LVGL 8 + TFT_eSPI，PlatformIO 构建 |
| 规模 | 9 个 FreeRTOS 任务、10 个界面；固件 1.94 MB（Flash 12.3%）、静态 RAM 125 KB（38.3%） |

## 2. 架构：按"实时性 + 资源归属"拆任务

```
core 1 ┐ lvgl        UI 8 KB / prio 3   ← 唯一允许访问 LVGL 的任务（唯一常驻节拍 5 ms）
       │
core 0 ┤ ina226      4 KB / prio 2   有需求才采：界面/输出打开 100 ms，主菜单只要电池 1 s
       │ uart        4 KB / prio 2   串口助手或 BLE 打开时 20 ms
       │ dso         3 KB / prio 2   RUN 时 1 kHz ADC 采样
       │ freq        3 KB / prio 2   RUN 时 125 ms 刷新（PCNT 硬件计数）
       │ ble        10 KB / prio 2   Nordic UART 服务（打开才初始化协议栈）
       │ power       3 KB / prio 2   DC 开关 + MP28167 调压（纯事件触发）
       │ pwm         3 KB / prio 1   LEDC 输出（硬件输出，任务只在设定值变化时动作）
       └ i2cscan     4 KB / prio 1   总线扫描（有请求才醒）
以上 8 个外设任务：前端没调用时一律阻塞在 ulTaskNotifyTake(portMAX_DELAY)，CPU 占用 0
中断：仅 1 ms 硬件定时器 → lv_tick_inc()，给图形库供心跳
```

- **UI 独占 core 1**：core 0 上有无线协议栈，抖动会直接变成掉帧，物理隔离比调优先级可靠；
- **优先级分三档**：体验敏感的 UI 最高，采样/通信次之，控制类最低，避免慢任务压住数据通路；
- **不做无谓唤醒**：只有"屏幕一直在显示"的 UI 任务需要固定 5 ms 节拍，其余任务按需唤醒（见 ⑥）；
- **栈按调用深度预留**：无线协议栈最深给 10 KB，其余 3–4 KB，上线前用 `uxTaskGetStackHighWaterMark()` 实测水位再收敛。

## 3. 六个关键设计

### ① 图形库线程安全：单访问者模型（不加锁）

LVGL 没有内部锁、回调可能在任何上下文触发。这里**不做"到处加锁"**，而是规定：
**LVGL 只在 UI 任务（含其内部定时器与事件回调）上下文中被访问**，其余 8 个任务一行控件代码都不碰。
竞态、重入、死锁从结构上不存在，代价是 0；只用一把递归互斥量 `app_lvgl_lock()` 兜住 UI 任务自身的临界区。

### ② 任务 ↔ 界面：三条数据通道，按数据形态选

| 数据 | 通道 | 理由 |
| ---- | ---- | ---- |
| 文本（UART / BLE / 扫描结果） | Stream Buffer ×3（4 KB/条） | 单读单写字节流，不定长、零拷贝、开销低于 Queue |
| 测量值（电压/电流/功率/mAh） | 互斥量保护的共享结构 + **字符串快照** | 界面只读快照，不会取到半新半旧的数（数据撕裂） |
| 示波器波形 | 256 点环形缓冲 + **递增序号** | 界面按序号只取新增点，不丢点、不重复 |

关键约束：**界面侧的搬运定时器在关闭功能页时删除**——后台任务只写缓冲区、永不持有控件指针，因此不可能写到已销毁的控件上。
（v2 界面把"离开界面"细化为"关闭某一个功能页"：多页可以同屏，每个页面的搬运定时器各归各的，
定时器随 `exlink_open_function()` / `exlink_close_function()` 建立与删除。）

### ③ 多功能并行 + 状态可视化

功能开关与界面解耦：开关只切界面，不切功能。主菜单实时显示 `RUN n` 与运行中的功能名（PWR/PWM/UART/SCAN/DSO/BLE/FRE）并同步按钮/页面高亮；
**界面模型（v2，与 EXlink2.1 一致）**：点主菜单的功能键，该按键就地变成这个功能的功能页面
（宽 = 菜单列宽、高 = 内容自适应），页面右下角的 × 关掉它菜单按键就回来；多个功能页可以同时开着，
所以"返回"从"重建整个主菜单"变成了"关掉当前焦点所在的页面"；旋钮的焦点单位是整页而不是页内控件；
示波器、频率计另有独立 **RUN/STOP**，支持"开一次、后台常驻"——也顺带避免了"忘了关输出"。

### ④ 一条 I2C 三家抢：总线锁 + 差异化超时

触摸、INA226、MCP4017 共用 Wire，统一用总线互斥量，但超时按"人能不能感知"分级：

| 访问者 | 超时 | 拿不到锁时 |
| ------ | ---- | ---------- |
| 触摸（每帧读） | 20 ms | 直接跳过本帧，人眼无感，**界面永不卡** |
| MCP4017 / 探测 | 200 ms | 本次操作放弃，下次重试 |
| INA226 读值 | 200 ms | 保持上次读数，不阻塞采集节奏 |

### ⑤ 任务按需唤醒：前端不调用就阻塞（不空转轮询）

任务的"周期"只在**有需求**时成立。每个任务循环末尾统一调用
`app_task_wait(任务, 周期, 有没有需求)`：

| 情形 | 行为 | CPU |
| ---- | ---- | --- |
| 有需求 | `ulTaskNotifyTake(pdTRUE, 周期)`：按周期睡，状态一变立刻被打断 | 只在采样时占用 |
| 没需求 | `ulTaskNotifyTake(pdTRUE, portMAX_DELAY)`：真正阻塞 | **0** |

需求来自两条线，缺一不可：

- **功能开关**：`app_*_set()` / `app_set_output()` / `app_i2c_scan_request()` → `xTaskNotifyGive()` 唤醒对应任务；
- **界面**：打开/关闭功能页时登记 `app_ui_page_open(APP_PAGE_xxx)` / `app_ui_page_close(APP_PAGE_xxx)`
  （多页同屏 → 页面集合用位图表示），采样类任务据此判断"有没有人看"；
  `app_ui_page_set()` 保留旧的"只开这一页"语义（开机动画 / 主菜单 = 一个功能页都没开）。

三个由此得到的好处：

1. **省 CPU**：串口/BLE/扫描/示波器/频率计全关时，8 个外设任务全部阻塞，
   不再每 20–200 ms 醒一次看开关；
2. **响应更快**：通知会被计数保存（任务正忙也不丢事件），开关响应从"最坏一个轮询周期"
   变成即时——DC 输出从最坏 50 ms 降到立即生效；
3. **顺带减少硬件占用**：`freq` STOP 时连 PCNT 硬件计数一起暂停，`ble` 没打开就不初始化协议栈，
   `i2cscan` 第一次点 SCAN 才占用扫描引脚。

需求判定的粒度也按"人看不看得见"分档：`ina226` 在 DC POWER / Voltmeter 界面或输出打开时
100 ms 全量采样（输出开着就继续累计 mAh），只停在主菜单时降为 1 s 采一次电池（电池图标要显示），
其余页面直接阻塞；`pwm` 把设定值写进 LEDC 后由硬件持续输出，任务本身不需要周期唤醒。
`mAh` 改为按两次采样的真实时间间隔积分，比原来"假设循环正好 100 ms"更准。

### ⑥ 健壮性：模块不在也能用

- 模块探测**非阻塞化 + 按需化**：未接的模块只在有人用到时（功率/电压表界面或输出打开）
  每 5 s 重试，不挡开机；没需求时不扫描总线，其它功能照常可用；
- 长日志文本区超 4000 字符自动清空，长时间运行内存不增长；
- 交互统一：触摸 + 旋钮双输入（短按确认 / 长按返回 / 按键提示音），内置 Pin Map 彩色接线图，现场接线不必翻资料。

## 4. 成果

| 维度 | 结果 |
| ---- | ---- |
| 功能复用 | 单台设备 = 8 类仪器/工具，最多 **6 个功能同时在线**；工作台从"多台仪器 + 一堆线"变为"一台设备 + 一块屏" |
| 资源 | 固件 **1.94 MB**（Flash **12.3%**）、静态 RAM **125 KB**（**38.3%**，含完整图形库 + 无线协议栈） |
| 实时性 | 界面刷新 **5 ms**、示波器 **1 kHz 采样 / 256 点**、频率计 **125 ms**、电流电压监测 **100 ms** |
| CPU | 前端未调用的功能任务全部阻塞（0 周期唤醒、0 CPU 占用）；开关响应由"轮询延迟"变为即时 |
| 工程质量 | PlatformIO 全量编译通过、源码零告警；功能后台常驻且状态可视化 |

## 5. 取舍与后续

- **取舍**：选择"单访问者 + 数据通道"而不是给图形库加锁——少一处锁就少一处死锁与优先级反转，代价是界面刷新必须由 UI 侧定时器搬运（略微增加延迟，但 5 ms 节拍下人不可感）。
- **取舍**：功能"后台常驻"与"不占 CPU"并不矛盾——常驻的是**功能状态**（开关、设定值、硬件输出），
  不是任务的轮询循环；前端不用时任务阻塞，被唤醒后立刻恢复工作。代价是每个任务要显式维护
  "需求从哪来"，比一句 `vTaskDelay` 轮询多一点设计成本。
- **后续可做**：栈水位继续收敛；采样改 DMA/中断触发提升带宽；串口通道换双缓冲减少拷贝；用 `vTaskGetRunTimeStats()` 做任务负载可视化；PC 端仿真平台（见 `EXlink2.0/README.md`）承接界面回归测试。
