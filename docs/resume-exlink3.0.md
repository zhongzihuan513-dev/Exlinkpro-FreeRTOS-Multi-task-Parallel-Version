## 【2026/XX】 - 2026/08

## Exlink3.0 —— 基于三主控架构的掌上多功能调试器
**个人开发者**｜嵌入式软件（固件架构 + 交互设计）+ 整机系统集成

**技术栈**：ESP32-S3 / RP2040 / CH549、FreeRTOS(SMP)、LVGL 8、TFT_eSPI、Arduino-ESP32、PlatformIO、C/C++、
CST816T 触摸、旋转编码器、I2C（INA226 / MCP4017）、ADC、LEDC/PWM、PCNT、UART、BLE、
sigrok 逻辑分析仪、DAPLink 调试器、双板叠板与多主控电源共地

**背景**：调试台上的工具是散的——供电、激励、测量、总线扫描、无线调试、代码下载仿真分属多台仪器与模块，
接线多、切换慢，传统仪器"一台一次只干一件事"，工具反而打断工作流。
目标是做一台 320×240 触摸手持设备，覆盖 **10 类功能**（数控电源、电压表、PWM 源、简易示波器、频率计、
串口助手、BLE 串口、I2C 扫描 + 引脚图、逻辑分析仪、DAPLink），且**功能可同时在线**。

**做法（技术实现）**：

1. **整机架构：三主控分域**。10 类功能中逻辑分析仪需高码率采样、DAPLink 需 USB 透传调试流，
   而主控 ESP32-S3 的算力、内存与 GPIO 已被另外 8 类仪器、图形库和无线协议栈占满，硬塞会抢展示波器
   采样节拍与界面刷新。故按能力特性分域：ESP32-S3 承载仪器与界面，RP2040 跑 sigrok 固件做逻辑分析仪，
   CH549 跑 WCH-Link 固件做 DAPLink；两颗芯片在信号板上**独立占用 USB 通道直连上位机、完全不经过主控**，
   不占其 RAM/Flash/GPIO/中断，上位机侧三个 USB 设备各自枚举、互不抢占。集成工作集中在引脚分配
   （避开已占用的 GPIO5 等既有定义）、独立取电与**单点共地**（避免采样电流串扰 INA226 与 ADC）、
   固件烧录（uf2 / WCHISPTool），**主工程构建流程零改动、零维护成本**。
2. **主控固件：9 个 FreeRTOS 任务**。按"实时性 + 资源归属"拆分，UI 固定 core 1（避开 core 0 上无线
   协议栈抖动），外设任务集中 core 0，按实时性分级设优先级与栈深（UI 8 KB / 协议栈 10 KB / 1 kHz 采样
   / 控制类最低），中断只留 1 ms 硬件定时器做图形库心跳。任务**按需唤醒**而非周期轮询常驻：
   前端没调用的功能任务阻塞在任务通知上（CPU 占用 0，STOP 的频率计连 PCNT 计数一起暂停，
   未用到的引脚/协议栈不初始化），开关与换界面即刻唤醒，响应还从"最坏一个轮询周期"变成即时。
3. **图形库线程安全——单访问者模型**。LVGL 只在 UI 任务（含其内部定时器与事件回调）中访问，其余 8 个任务
   不碰任何控件，从结构上消除重入、死锁与"边画边改"竞态，而非到处加锁。
4. **任务 ↔ 界面三条数据通道**：文本类（串口 / BLE / 扫描结果）走 **Stream Buffer（3 × 4 KB）**；
   测量值用**互斥锁共享结构 + 字符串快照**（杜绝数据撕裂）；波形用 **256 点环形缓冲 + 递增序号**
   （界面只取增量，不丢不重）。界面侧搬运定时器随界面销毁而删除，保证后台任务**永不持有已销毁的控件指针**。
5. **多功能并行 + 状态可视化**。功能开关与界面解耦：返回主菜单不关功能，仪器继续后台工作；主菜单实时显示
   `RUN n` 与运行中的功能名并同步按钮高亮；示波器、频率计另有独立 RUN/STOP，支持"开一次、后台常驻"。
6. **一条 I2C 三家抢——总线锁 + 差异化超时**。触摸、INA226、MCP4017 共用 Wire，超时按"人能否感知"分级：
   触摸 20 ms（拿不到即跳过本帧，界面永不卡）、MCP4017 200 ms（本次放弃、下次重试）、
   INA226 500 ms（保持上次读数）。模块探测非阻塞化（未接模块后台每 5 s 重试，不挡开机），
   长日志超 4000 字符自动清理，长时间运行内存不增长。
7. **共存回归验证**。实测逻辑分析仪采集中、DAPLink 挂载调试目标时，ESP32-S3 上数控电源输出、PWM 输出、
   频率计数、电流电压监测、串口/BLE 收包、I2C 扫描全部正常，**无复位、无死机、无串口异常**。

**成果**：单台设备覆盖 **10 类仪器/工具**，最多 **6 个功能同时在线**，工作台从"多台仪器 + 一堆线"变为
"一台设备 + 一块屏"。主控侧固件 **1.94 MB**（Flash **12.3%**）、静态 RAM **125 KB**（**38.3%**，含完整图形库
与无线协议栈）；界面刷新 **5 ms**、示波器 **1 kHz / 256 点**、频率计 **125 ms**、电流电压监测 **100 ms**
（空闲时 8 个外设任务全部阻塞，只有 UI 任务保持 5 ms 节拍）。
三主控分域使"逻辑分析仪采集 + DAPLink 调试 + 数控电源供电 + 频率计计数"可同时进行，
且**主控固件一行未改、既有 8 类仪器零回归**；PlatformIO 全量编译 43 s 通过、源码零告警，可现场演示。

### 2. 60–90 秒口述版

> 我做的是 Exlink3.0，一台掌上多功能调试器。起因是调试台工具太散：供电、测量、串口、总线扫描、
> 下载仿真分属好几台仪器，接线多、切换慢，仪器反而打断工作流，所以我想用一台触摸手持设备全收进去，
> 一共 10 类功能，并且能同时在线。
> 架构上做了分域：ESP32-S3 负责仪器和界面，上面用 FreeRTOS 开了 9 个任务、做了双核绑定，UI 独占一核；
> 图形库不是线程安全的，我没到处加锁，而是规定只有 UI 任务能碰控件，其它任务只往 Stream Buffer、
> 环形缓冲和互斥共享结构写数据，由界面定时器搬运刷新；触摸、电流芯片和数字电位器共用一条 I2C，
> 我加了总线锁和差异化超时，触摸拿不到锁就跳过本帧，界面永不卡。
> 逻辑分析仪和 DAPLink 我没塞进主控——S3 的算力和引脚已经占满，硬塞会抢掉示波器采样和界面刷新，
> 所以信号板上各加一颗专用芯片，RP2040 跑 sigrok、CH549 跑 WCH-Link，信号直连上位机、不经过 ESP32-S3。
> 最终固件只占 1.94 MB Flash、125 KB 静态 RAM，就支撑 10 个界面和 6 个功能同时在线；
> 逻辑分析仪采集中、DAPLink 调试目标板的同时，数控电源、频率计、串口照常工作，主控零复位。

### 3. 高频追问

1. **为什么上 RTOS 不用轮询？** —— 场景是"边供电、边测频、边看串口"，轮询只能排队且必须来回切界面；
   多任务让功能并行常驻，工具才"不打断人"。
2. **为什么 LVGL 只让一个任务访问？** —— 图形库无内部锁、回调可在任意线程触发；单访问者模型从结构上
   消除重入与死锁，比散落加锁更可靠、开销更小。其它任务是生产者，只写缓冲区，界面定时器消费。
3. **Stream Buffer 与 Queue 区别？** —— Queue 按定长消息搬运（拷贝与校验开销），Stream Buffer 是
   单读单写字节流，匹配串口/BLE 这类不定长数据。
4. **优先级和栈怎么定？** —— UI 最高，采样/通信次之，控制类最低；栈按调用深度预留（协议栈 10 KB），
   上线前用 `uxTaskGetStackHighWaterMark()` 实测水位再收敛。
5. **触摸和设备抢 I2C 怎么办？** —— 总线互斥量 + 差异化超时，触摸 20 ms 拿不到跳过本帧，外设 200–500 ms，
   绝不长时间占用总线；共享资源用带优先级继承的互斥量。
6. **为什么不用 S3 自己做逻辑分析仪和 DAPLink？** —— 已占满，且高码率采样与 USB 透传会抢走采样节拍和
   UI 时间，改动既有任务架构会让回归面覆盖整机；用专用芯片是"用一颗几块钱的芯片换掉一次高风险重构"。
7. **三者靠什么不冲突？** —— 算力不共享（不同芯片）、数据路径不交叉（USB 直连上位机，不经主控）、
   电气独立取电 + 单点共地（避免采样电流串扰模拟测量）。
8. **最大取舍？** —— 放弃"全自研、全在主控"的一致性，换取能力完整 + 主控零改动 + 零维护成本；
   代价是多一颗芯片、一块板，以及多一套上位机工具的使用门槛。
